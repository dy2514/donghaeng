# 실제 경로 등록과 검증

이 앱의 예시 경로 ID는 campus-practice이며 구간은 school-right / school-eastbound와 gate-left / gate-northbound 두 개입니다. 이 ID는 앱 내부의 학습 구간이며 실제 내비 경로 ID가 아닙니다.

## 등록

1. 시험 환경의 기본 내비에서 재현 가능한 한 경로를 준비합니다.
2. 각 연습 구간의 실제 좌표, 진입 heading, currentRouteIndex 범위, 다음 TBT의 회전 종류와 거리, 해당 경로의 native routeId를 관찰합니다.
3. live-route.example.json을 복사하고 실제 관측값을 입력합니다. 좌표 0, 예시 경로 문자열과 인덱스는 교체해야 합니다. 구간명과 진입 ID는 위 앱 내부 ID를 유지합니다.
4. 반경·heading 허용차·TBT 거리 기준을 실제 시험 경로에서 확인하고 calibrated를 true로 바꿉니다. 이 플래그는 사용자 등록 확인이며 앱이 정확도를 인증한다는 뜻이 아닙니다.
5. 주차한 상태에서 앱의 연결 상태 → 실제 경로 JSON 가져오기로 등록합니다. Android 파일 선택기로 접근 가능한 위치에 파일을 복사하세요.
6. 출발 준비에서 차량 연결을 선택하고 경로 준비 상태를 확인합니다. 보정 정보가 없거나 내비 조건이 일치하지 않으면 안내를 보류합니다.

## 상태 관찰

연결 상태 창에 플랫폼, 속도, 브레이크, 방향지시등, 주차·조작 허용, 기본 내비, 연습 경로 상태가 표시됩니다. 원시 SDK 데이터가 반환되었다는 사실과 실제 구간이 검증되었다는 사실은 다릅니다. 먼저 실제 경로와 조건을 검증한 뒤 세션을 시작합니다.

앱은 경로를 생성하거나 내비 목적지를 변경하지 않습니다. 재탐색·경유지·목적지 변경 등으로 조건이 바뀌면 보정 경로를 다시 확인하고 새 세션을 시작해야 합니다. TBT가 구간을 벗어났다고 판정하면 기록이 끝나므로, 회전 후 구간까지 기록하려면 실제 경로 테스트를 거쳐 유지 조건을 확장해야 합니다.

## 콘솔

에뮬레이터는 scripts/Start-Emulator.ps1로 Cold Boot합니다. RUN_APP.cmd는 포트 8088 전달을 설정합니다. 브라우저에서 http://127.0.0.1:8088 로 접속합니다. 현재 이미지에서 emulator_inactive 응답이 관찰되어 동적 검증은 미완료입니다. 공식 이미지/도구 조합과 DDS 브리지 상태를 먼저 점검하세요.

## 음성·주행 전환

목표별 안내는 최대 1회입니다. 포커스를 얻지 못하거나 상실하면 보류한 음성을 나중에 재생하지 않습니다. 기본 내비와 통화를 포함해 실제 플랫폼에서 확인해야 합니다. P 기어와 플랫폼 조작 허용이 확인되지 않으면 복습·설정 화면을 잠급니다.
